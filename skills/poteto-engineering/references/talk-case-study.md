# Lauren Tan 的工程实践案例

[AI Engineer CODE 2026 演讲《All Code Is Slop (Except Mine)》](https://ai.engineer/code/2026/talks/lauren-tan)。以下用于选择项目实践，数据口径见 `references/provenance.md`。

| 演讲案例 | 如何在自己的项目落地 |
| --- | --- |
| Grok Bot 的 Electron 框架 Dune 在框架层收拢 React 副作用入口，并检查主进程与渲染进程的依赖边界 | 找出反复误用的 API，用更窄的接口表达正确做法。验证 import 规则能拦住越界调用，同时允许项目支持的 IPC 契约和共享类型。以项目证据决定是否需要局部限制某个 API |
| Cursor 客户端曾出现定时器补丁被复制，Dune 用清晰的 Lint 报错指引修正 | 让报错说明违反了哪条规则、为什么，以及可用的替代路径。保留解释设计取舍和边界条件的注释 |
| Feature Map 配合运行工具和复用 CLI | 用用户术语定位功能，给关键路径配实际操作、状态断言和证据入口。能用现有驱动完成时直接复用 |
| TLA+ 检查跨设备通知，Lean 检查虚拟化算法的性质 | 先写出“哪些状态必须始终成立”，再选择模型检查或证明。用运行测试核对模型和实现，界面闪烁另用实测观察 |
| Bombadil 探索 UI 动作序列并检查属性 | 在隔离测试环境定义可观察的属性，记录失败序列并重放。稳定失败可沉淀为回归测试。工具按项目选择 |
| 通过录屏、截图、状态图和验证结果审查实际行为 | 将每条验收条件对应到证据。用状态图确认流程，用运行记录确认实现，用验证器输出确认其明确覆盖的性质 |
| 发布时触发客户端功能探索和修复 | 先以单条隔离测试流程试点。扩大范围前检查复现率、误报、成本和现有合并门槛 |

把重复出现、可判定的错误优先交给代码约束。额外的 Token 投到能降低不确定性的复现和检查，团队可按任务风险分配预算。
